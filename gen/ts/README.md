# @fair-n-square-co/apis

Generated TypeScript types and Connect-RPC service descriptors for the fairnsquare
APIs, built from the protobuf definitions in `proto/` with
[protobuf-es](https://github.com/bufbuild/protobuf-es) v2.

Published to **GitHub Packages** as `@fair-n-square-co/apis`.

> **Note:** `src/` is auto-generated by `buf generate` — do not edit it by hand.
> Change the `.proto` files and re-run `make gen`.

## Installation

GitHub Packages requires authentication, so consumers need two things.

**1. An `.npmrc` pointing the scope at GitHub Packages:**

```ini
@fair-n-square-co:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

**2. A `GITHUB_TOKEN` in the environment** — a classic PAT with the `read:packages`
scope. In CI, the workflow's built-in `secrets.GITHUB_TOKEN` is enough, provided the
job grants `permissions: packages: read`.

Then:

```bash
bun add @fair-n-square-co/apis
```

## Usage

Under protobuf-es v2 the service descriptor lives in the `*_pb` module alongside its
messages — there are no separate `*_connect` files. Import the service and hand it to
`createClient` from `@connectrpc/connect`:

```typescript
import { createClient } from '@connectrpc/connect';
import { createConnectTransport } from '@connectrpc/connect-node';
import { ProfileService } from '@fair-n-square-co/apis/fairnsquare/service/authx/v1alpha1/profile_api_pb';
import { IdentityService } from '@fair-n-square-co/apis/fairnsquare/service/authx/v1alpha1/authx_api_pb';

const transport = createConnectTransport({
  baseUrl: 'http://localhost:8080',
  httpVersion: '1.1',
});

const profileClient = createClient(ProfileService, transport);
const identityClient = createClient(IdentityService, transport);

const { user } = await identityClient.resolveUser({});
const { profile } = await profileClient.getProfile({});
```

This package depends only on `@bufbuild/protobuf`; the connect runtime and a transport
are the consumer's to install.

### Importing types

```typescript
import type { Profile } from '@fair-n-square-co/apis/fairnsquare/service/authx/v1alpha1/profile_types_pb';
import type { User } from '@fair-n-square-co/apis/fairnsquare/service/authx/v1alpha1/authx_types_pb';
import type { Transaction } from '@fair-n-square-co/apis/fairnsquare/service/transaction/v1alpha1/transaction_pb';
```

Subpaths mirror the protobuf package path. There is intentionally **no root export**: a
single barrel would collide on common type names (`User`, for instance, exists in more
than one package), so import from the specific `*_pb` subpath.

## Releasing

TypeScript releases are versioned independently of the Go bindings (`gen/pkg/v*`), and
the published version is derived from the tag:

```bash
git tag gen/ts/v0.1.0
git push origin gen/ts/v0.1.0
```

That triggers `.github/workflows/release-ts.yml`, which builds `dist/`, stamps the
version from the tag, and publishes to GitHub Packages.

## Development

- `bun run typecheck` — type check the generated code
- `bun run build` — emit `dist/` (`.js` + `.d.ts`) via `tsconfig.build.json`
